# 032 — ESLint sur le code Node (daemon, contract, bin, electron)

- **Statut :** Acceptée
- **Date :** 2026-11-17
- **Décidé par :** Toi

## Contexte
Aucun linter : variables inutilisées, affectations mortes et autres erreurs évitables ne sont vues qu'à la relecture. La CI ne lançait que les tests et le build.

## Décision
- Trois devDependencies à la racine : `eslint`, `@eslint/js` (règles `recommended`) et `globals` (globals Node). Rien d'autre : ni Prettier, ni plugin.
- `eslint.config.mjs` (config plate) : `recommended`, ESM, globals Node ; `ui/`, `node_modules/` et `dist/` exclus (l'UI a sa propre chaîne). Aucune règle de style.
- `no-unused-vars` avec `ignoreRestSiblings` : `const { MISE_YES: _yes, ...reste } = env` est la façon voulue de retirer une clé.
- `npm run lint` avant les tests dans la CI.

## Raisons
- Outil standard, sans configuration lourde ; devDependencies seulement, rien n'entre dans l'app empaquetée.
- Les règles `recommended` attrapent de vrais défauts sans imposer de style.

## Alternatives écartées
- Prettier ou règles de style : bruit, aucun défaut réel évité.
- `node --check` : ne voit que la syntaxe.

## Conséquences
- Une nouvelle règle qui gêne se règle dans `eslint.config.mjs` avec sa raison, ou par un `eslint-disable-next-line` justifié.
