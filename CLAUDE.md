# Vigie

Tour de contrôle locale des sessions Claude Code. Produit : `PRODUCT.md`. Système visuel : `DESIGN.md`. Fonctionnement : `README.md`. Décisions et leurs raisons : `decisions/` (une décision structurante = un nouveau fichier `AAAA-MM-JJ-NNN-titre.md` ; on ne réécrit pas une décision, on la remplace). Une décision citée dans le code ou la doc existe dans `decisions/` et dans son README, écrite dans la même tâche que le code qui la cite ; elle met à jour la doc qu'elle touche (`DESIGN.md`, `ARCHITECTURE.md`, `README.md`).

## Carte du dépôt

- `daemon/` : Node 24, ESM `.mjs`, sans framework (`node:http`, `ws`, `node-pty`). Possède les PTY, ingère les transcripts, pousse l'état par WebSocket.
  - Architecture, sens des dépendances et « où ajouter quoi » : **`daemon/ARCHITECTURE.md`** (à lire avant toute modification du daemon).
  - `server.mjs` point d'entrée (câblage, effets de bord, `listen`) · `transport.mjs` HTTP, WebSocket, PTY · `store.mjs` état en mémoire (`history.mjs` fichier d'historique, `trace.mjs` trace en tours, pur) · `usage.mjs` consommation (pur) · `ingest.mjs` lecture des transcripts (pur) · `guard.mjs`, `launch.mjs` fonctions pures du transport · `platform.mjs` tout ce qui dépend de l'OS (pur, macOS/Linux/WSL) · `git.mjs`, `claude-config.mjs` adaptateurs · `plugins.mjs` chargeur et SDK des plugins · `hook.mjs`, `statusline.mjs` scripts lancés par Claude Code · `pricing.mjs` tarifs · `claude-status.mjs` statut de Claude (seule requête sortante faite par le daemon lui-même, décision 024 ; l'autre sortie, décision 046, passe par le binaire `claude` lancé par `git.mjs`) · `files.mjs` explorateur de fichiers · `projects.mjs` sélecteur de projets · `paths.mjs` chemins partagés (`~`, dossier de config Claude, pur) · `settings.mjs` réglages du daemon et locales.
  - Ne jamais importer ni lancer `daemon/server.mjs` dans un test ou un script : il démarre un daemon, écrit dans `~/.vigie` et purge des discussions. Tester via `createTransport` / `createStore`.
- `plugins/<id>/` : plugins locaux livrés avec l'app (mise, xcode, npm, nx ; décisions 034, 037, 038), désactivés par défaut. Back : `index.mjs` chargé par `daemon/plugins.mjs` (lui et ses modules n'importent que `node:*` et leurs fichiers) ; schémas propres : `contract.mjs` ; front : `ui/index.ts` (composant Angular, compilé avec l'app ; parle à Vigie uniquement par `@vigie/plugin-sdk` ; imports par liste d'autorisés vérifiée par ESLint : `@vigie/plugin-sdk`, `@angular/*` hors `@angular/common/http`, `@spartan-ng/helm/*`, `zod/mini`, son `../contract.mjs` et ses fichiers TypeScript `./x`, plus `@vigie/plugin-sdk/testing` et `vitest` dans les specs ; ni réseau direct, ni navigation hors de l'UI, ni HTML de confiance, ni `import()` dynamique, décision 037), table générée par `scripts/plugin-uis.mjs` dans `ui/src/app/core/plugin-uis.generated.ts` (commitée). Écrire un plugin : `docs/plugins.md`.
- `contract/` : workspace `@vigie/contract`, schémas **Zod** (`zod/mini`) du contrat daemon ↔ UI. Le daemon l'importe par chemin relatif (`../contract/index.mjs`, seul `transport.mjs`) ; l'UI par son nom de paquet.
- `ui/` : Angular 22, signaux, spartan/ui (`ui/libs/ui`, alias `@spartan-ng/helm/*`), Tailwind v4, xterm.js, Transloco (catalogues `ui/src/i18n/`, décision 048).
- `electron/main.mjs` : app de bureau, lance toujours son daemon et l'arrête en quittant ; un daemon déjà lancé est arrêté après confirmation par `POST /api/shutdown`, jamais un service installé (décision 050).
- `bin/vigie.mjs` : CLI (sans argument : démarre le daemon s'il ne tourne pas, puis ouvre l'UI ; `start`, `status`, `install`, `uninstall` ; service launchd ou systemd --user).

## Commandes

- Workspaces npm (`ui`, `contract`) : `npm install` **uniquement à la racine** (un seul lockfile, une seule copie de zod).
- Tout : `npm test` · lint : `npm run lint` · daemon seul : `node --test daemon/*.test.mjs plugins/*/*.test.mjs scripts/*.test.mjs` · UI seule : `npm test -w ui -- --no-watch`
- Dans le sandbox : `VIGIE_NO_PTY=1 node --test daemon/*.test.mjs plugins/*/*.test.mjs scripts/*.test.mjs` (le sandbox interdit posix_spawnp ; saute le seul test qui ouvre un vrai PTY, qui sinon doit passer).
- Build UI : `npm run build` (dans le sandbox : `cd ui` puis `CI=1 npx ng build --progress=false`, sinon la sortie est muette).
- Paquet de l'app : `npm run dist` (dans le sandbox : `CI=1 npm run dist`).
- npm dans le sandbox : `--cache "$TMPDIR/npm-cache"` (le cache global n'est pas inscriptible).
- Dépôt git (`origin` = `git@github.com:Cedric-locchi/claude-vigie.git`, branche `main`) : `git status` / `git diff` pour voir ce qui a changé ; on ne commite et ne pousse que sur demande.

## Règles non négociables

- Local uniquement : le daemon écoute sur 127.0.0.1 ; WebSocket, POST et tout GET `/api/*` refusent les origines étrangères (`Origin`, `Sec-Fetch-Site`) ; aucune requête vers l'extérieur (polices embarquées comprises).
  - Deux exceptions, pas d'autre sans décision : (024) le daemon fait un `GET https://status.claude.com/api/v2/summary.json` toutes les 5 min, sans rien envoyer ; (046) sur ton clic seulement, la suggestion de message de commit lance `claude -p` depuis `~/.vigie/commit-message` (dossier vide ; sans outils, persistance, MCP ni réglages du projet ou de l'utilisateur) avec le diff (sans diff externe ni textconv, tronqué), les noms des fichiers non suivis (200 au plus) et les derniers titres de commit. L'UI ne sort jamais : le daemon la sert sous une CSP qui interdit toute ressource extérieure, et le Markdown n'est rendu que par `ui/src/app/core/markdown.ts`, qui retire les images distantes (décision 044).
- La config Claude Code globale de l'utilisateur (`~/.claude`, `~/.claude.json`, le dossier `CLAUDE_CONFIG_DIR` s'il est défini) n'est jamais modifiée : hooks et statusline passent par `claude --settings`, seulement pour les sessions lancées par Vigie. Toute écriture ou suppression de fichier par le daemon passe par la garde de la fonction partagée qui la fait (`underClaudeConfig`, `purge` → `isChat`), jamais par une vérification laissée à l'appelant.
  - Exception unique : une discussion (session lancée par Vigie avec `cwd` = `~/.vigie/chat`) est effacée du dossier des transcripts (`projects/` du dossier de config Claude : `$CLAUDE_CONFIG_DIR`, sinon `~/.claude` ; transcript + dossier des sous-agents) quand on la quitte et au démarrage du daemon. Seul un transcript dont le `cwd` est ce dossier est concerné (`store.isChat` garde la route de suppression, `store.purge` efface, `store.purgeChats` au démarrage).
- Contrat daemon ↔ UI : **`contract/index.mjs` est la source unique**. `ui/src/app/core/models.ts` n'en contient que des `z.infer` ; on ne déclare jamais un type du contrat à la main. Un champ change → schéma, sortie du daemon, son test `conforme(...)` et le mock UI dans la même tâche, toujours de façon additive. Le daemon valide ses entrées avec le contrat, l'UI valide tout ce qu'elle reçoit (`safeParse` → bandeau / message « le daemon est-il à jour ? »). Nouvelle valeur d'enum = daemon et UI ensemble (un snapshot inconnu est rejeté en entier).
- Toujours `import * as z from 'zod/mini'`, jamais `import { z } from 'zod'` (taille de l'app et du bundle UI).
- Les règles vérifiables mécaniquement sont dans ESLint (`eslint.config.mjs`), qui attrape leurs formes usuelles ; un contournement délibéré reste à la relecture (`daemon/ARCHITECTURE.md`, « Non couvert »). Elles portent sur :
  - `zod/mini` (`import()` compris) ;
  - `server.mjs` jamais importé (`import()` compris, UI comprise) ;
  - CommonJS : `require()` refusé sauf `require('electron')` dans un `.cjs` (seul `electron/preload.cjs` existe) ; l'ESM n'a pas de `require` ;
  - contrat importé dans `daemon/` par `transport.mjs` seul, tests exceptés (la CLI l'importe aussi, pour valider le snapshot de `vigie status`) ;
  - imports par liste d'autorisés (daemon : `node:*`, ses modules `./x.mjs`, `../contract/index.mjs`, `ws`, `node-pty`, `zod/mini` ; `bin/` et `electron/` : `node:*`, leurs fichiers, `../daemon/*.mjs`, `../contract/*.mjs`, `electron` ; back d'un plugin : `node:*` et ses fichiers `.js` / `.mjs` hors de son `ui/` ; front d'un plugin : SDK, Angular, spartan, `zod/mini`, son contrat et ses fichiers TypeScript) ;
  - plateforme côté Node, dans `daemon/` (tests compris), `bin/`, `electron/`, `scripts/`, `contract/`, tout `.cjs` et le back des plugins (pas leurs tests) : aucune propriété `platform` lue hors de `platform.mjs`, sauf `{ platform: process.platform }` dans `server.mjs`, `bin/` et `electron/` ; ni `os.type()` ; l'UI a son propre point, `ui/src/app/core/platform.ts`, non vérifié par le lint ;
  - réseau sortant hors de `claude-status.mjs` dans `daemon/` et le back des plugins (`dns`, `createRequire` et `getBuiltinModule` compris) ; dans `bin/` et `electron/` (fichiers `.js` compris), idem (`node:http`, `WebSocket`, le `net` d'Electron, `session.fetch`, `downloadURL` et tout `import()` compris), sauf `fetch` vers le daemon local (`${ORIGIN}/…`) ; dans `scripts/` et tout `.cjs`, modules réseau, `fetch`, `WebSocket`, `EventSource` et `getBuiltinModule`, plus tout `import()` et toute plateforme lue (`.cjs` compris) (`createRequire` reste permis dans `scripts/` : il y résout `@angular/core`).

  Une nouvelle règle de ce genre = une règle ESLint, pas seulement une phrase ici.
- Plateformes : **macOS et Linux** (Windows via WSL). Aucun nouveau code propre à un OS hors d'un point de plateforme isolé et testé pour les deux ; chemins via `path`, jamais de `/` en dur.
- UI en français (langue source) et en anglais (décision 048) : dans une page traduite, tout texte de l'UI passe par `ui/src/i18n/fr.json` et `en.json` (mêmes clés, jamais de HTML) ; les messages du daemon et du contrat (validations Zod comprises) restent en français (`ponytail:` de `ui/src/app/core/language.service.ts`) ; français au tutoiement. Les pages pas encore traduites restent en dur en français. Commentaires de code en français.
- Pas de nouvelle dépendance sans raison écrite ; stdlib et plateforme d'abord.
- Raccourci assumé = commentaire `ponytail:` qui nomme la limite et la suite.
- Toute session qui modifie le code passe, avant le bump de version, l'agent `doc-auditor` sur les fichiers changés et corrige ses dérives dans la même session : la doc décrit le code réel ; seul un code qui viole une règle ou une décision change à la place de la doc (décision 047).
- Toute session qui modifie le code se termine par un bump de version : `npm version <niveau> --no-git-tag-version` à la racine (met à jour `package.json` et `package-lock.json`, sans tag). Un seul bump par branche : si `git diff main -- package.json` montre déjà un bump, on ne le remonte que si le niveau requis est plus haut.
  - **majeur** : rupture : champ du contrat retiré ou renommé, nouvelle valeur d'enum qu'une UI plus ancienne rejette, route supprimée, format de `~/.vigie` incompatible, commande CLI changée.
  - **mineur** : nouvelle fonctionnalité visible ou champ ajouté au contrat (additif).
  - **patch** : correction, refactor, tests, docs, tooling, sans changement visible.
  - Le niveau retenu et sa raison figurent dans le compte rendu.
